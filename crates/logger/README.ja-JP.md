# VRCX-0 セルフホストレコーダー（試験的）

[English](README.md) | [简体中文](README.zh-CN.md) | [繁體中文](README.zh-Hant.md) | **日本語** | [한국어](README.ko-KR.md)

セルフホストレコーダーは常時稼働するマシン上で動作し、VRCX-0 を閉じている間のフレンドのアクティビティを記録します。VRCX-0 の起動後、その間の記録がローカルのフィードに補完されます。

> [!WARNING]
> 試験的な機能です。レコーダーはあなたのアカウントで別の IP アドレスから VRChat にログインします。VRChat のポリシーやセキュリティチェックにより、切断や再認証の繰り返しが起きることがあり、最悪の場合はアカウントの制限や BAN の可能性があります。自己責任でご利用ください。ログイン情報はご自身のレコーダーにのみ送信されます。

## 対象

- 補完するもの：フレンドのオンライン・オフライン、現在地、ステータス、アバターの変更。VRCX-0 で「フレンドの自己紹介を自動で取得」をオンにしている場合は自己紹介の変更も補完します。
- 1 台のレコーダーで扱えるのは 1 つの VRChat アカウントです。
- 補完しないもの：
    - VRCX-0 のクラッシュ・強制終了・スリープ・接続切れの後の約 30 秒；
    - 記録の区切りでまだ確定していないオフライン；
    - レコーダー自身が VRChat から切断されていた間の変化。

## 動作環境

- 常時稼働するマシン。NAS、VPS、Raspberry Pi などの Linux（x86_64 または ARM64）か、Windows PC（x86_64）。
- Docker と Docker Compose v2（`docker compose` コマンド）。単体の実行ファイルも提供しています。
- VRCX-0 からネットワーク経由で接続できること。

## インストール

### インストールスクリプト

```sh
curl -fsSL https://raw.githubusercontent.com/Map1en/VRCX-0/master/crates/logger/install.sh | sh
```

インストール先、リリースチャンネル、ポート、待ち受けアドレス、保存日数、容量の上限、パスワードを順に尋ねます。Enter で角かっこ内の既定値を使います。その後コンテナを起動し、VRCX-0 に入力するアドレスとパスワードを表示します。設定はインストール先の `.env`、パスワードは `password` に保存されます。

- アップデート：スクリプトを再実行します。尋ねるのはリリースチャンネルだけで（既定値は現在のチャンネル）、`.env`、`password`、`compose.yaml` はそのまま残ります。ほかの設定を変えるときは `.env` を編集し、インストール先で `docker compose up -d` を実行します。
- 停止：`-s down` を付けます（`... | sh -s down`）。
- 現在のユーザーで Docker を使えない場合は `sudo sh` を使います。

### Docker Compose

```sh
mkdir vrcx-0-logger && cd vrcx-0-logger
curl -fsSLO https://raw.githubusercontent.com/Map1en/VRCX-0/master/crates/logger/compose.yaml
printf '%s' 'パスワード' > password
docker compose up -d
```

NAS の管理画面（Synology Container Manager、Unraid など）：イメージに `ghcr.io/map1en/vrcx-0-logger:latest` を指定し、ポート `8787` とフォルダーを `/data` に割り当て、環境変数 `VRCX0_LOGGER_PASSWORD` を設定します。Unraid では `/data` をキャッシュまたは単一ディスク上のパス（例：`/mnt/cache/appdata/vrcx-0-logger`）に割り当ててください。`/mnt/user` の共有では SQLite が壊れることがあります。パスワードを Compose ファイルの `environment:` に直接書く場合は、`$` を `$$` と書きます。

### リリースチャンネル

| タグ     | 対象                                  |
| -------- | ------------------------------------- |
| `latest` | 正式版の VRCX-0                       |
| `beta`   | ベータ版の VRCX-0                     |
| `x.y.z`  | 固定バージョン（例：`2.32.0-beta.1`） |

正式版の VRCX-0 は正式版のレコーダーにのみ接続します。

### 単体の実行ファイル

[Releases](https://github.com/Map1en/VRCX-0/releases) から `vrcx-0-logger_<バージョン>_linux_<アーキテクチャ>` をダウンロードし、パスワードの環境変数を設定して実行します。常駐させる場合は systemd などのサービス管理を使ってください。

### Windows

[Releases](https://github.com/Map1en/VRCX-0/releases) から `vrcx-0-logger_<バージョン>_windows_x86_64.exe` をダウンロードして起動します。VRCX-0 に入力するアドレスと自動生成されたパスワードがウィンドウに表示され、待ち受けアドレス、ポート、データフォルダー、保存期間、容量上限もここで変更できます。設定は `%LOCALAPPDATA%\VRCX-0 Logger\logger.env` に保存され、記録は既定で同じ場所の `data` フォルダーに置かれます。ウィンドウを開いている間はレコーダーが動作し、VRChat に接続できないといった接続の問題はステータスの下に表示されます。

ウィンドウなしで動かしたい場合（タスク スケジューラから起動するなど）は `--headless` を付けて起動し、「設定項目」の環境変数を設定してください。

### 設定項目

インストールスクリプトや Docker Compose で導入した場合は、インストール先の `.env` を編集して `docker compose up -d` を実行します。パスワードは `password` ファイルにあります。

| `.env` のキー                 | 既定値    | 説明                                                           |
| ----------------------------- | --------- | -------------------------------------------------------------- |
| `VRCX0_LOGGER_TAG`            | `latest`  | リリースチャンネル。                                           |
| `VRCX0_LOGGER_PORT`           | `8787`    | ホスト側のポート。                                             |
| `VRCX0_LOGGER_BIND`           | `0.0.0.0` | ホスト側の待ち受けアドレス。                                   |
| `VRCX0_LOGGER_RETENTION_DAYS` | 無制限    | この日数より古い記録を削除します。                             |
| `VRCX0_LOGGER_MAX_STORAGE_MB` | `1024`    | この容量（MB）を超えると古い記録から削除します。`0` で無制限。 |

単体の実行ファイルは次の環境変数を読み込みます。NAS の管理画面ではコンテナに設定します。

| 変数                          | 既定値                        | 説明                                                           |
| ----------------------------- | ----------------------------- | -------------------------------------------------------------- |
| `VRCX0_LOGGER_PASSWORD`       | 必須                          | 8 文字以上。通信とデータの暗号化に使います。                   |
| `VRCX0_LOGGER_PASSWORD_FILE`  |                               | パスワードをファイルから読み込みます。                         |
| `VRCX0_LOGGER_HOST`           | `0.0.0.0`                     | 待ち受けアドレス。                                             |
| `VRCX0_LOGGER_PORT`           | `8787`                        | 待ち受けポート。                                               |
| `VRCX0_LOGGER_DATA_DIR`       | `data`（Docker では `/data`） | データの保存先。                                               |
| `VRCX0_LOGGER_RETENTION_DAYS` | 無制限                        | この日数より古い記録を削除します。                             |
| `VRCX0_LOGGER_MAX_STORAGE_MB` | `1024`                        | この容量（MB）を超えると古い記録から削除します。`0` で無制限。 |

コンテナでは `VRCX0_LOGGER_HOST`、`VRCX0_LOGGER_PORT`、`VRCX0_LOGGER_DATA_DIR` を設定せず、ポートを変えるときはポートの割り当てを変更してください。

## VRCX-0 から接続する

**ツール → セルフホストレコーダー**：

1. 自動バックアップをオンにします。
2. レコーダーのアドレスを入力します（例：`http://192.168.1.10:8787`）。
3. レコーダーのパスワードを入力します。
4. レコーダーを VRChat にログインさせます。必要に応じて二要素認証を行います。

VRCX-0 とレコーダー間の通信はパスワードで暗号化されます。ポートをインターネットに公開しないでください。外部から使う場合は Tailscale などの VPN を使ってください。VPS では待ち受けアドレス（`.env` の `VRCX0_LOGGER_BIND`）を VPN のアドレスにするか、ファイアウォールでポートを制限してください。

## 使い方

- **ステータスバー**：プロキシのアイコンの隣にレコーダーの状態が表示されます。オレンジ：ログイン中、再接続中、別のアカウント、応答が異常。赤：接続できない、パスワードが違う、バージョンが合わない、VRChat へのログインや二要素認証のコードが必要。
- **補完**：VRCX-0 の接続後に自動で行われます。「今すぐ補完」で手動でも実行できます。VRCX-0 を通常終了すると、すぐにレコーダーへ引き継がれます。
- **Webhook**：Discord または POST を受け付ける任意の URL。ログインの停止、二要素認証が必要なとき、記録を保存できないとき、未補完の記録が容量の上限で削除されたとき、記録が再開したときに送信します。各メッセージの先頭に種類（`login`、`storage`、`recovered`、`test`）を示し、エラー時は元のエラー内容を添えます。
- **ヘルスチェック**：`GET /health` はレコーダーがデータベースを読み込めるときに 200 を返します。イメージに shell はないため、コンテナの外から監視してください。

## アップデート

インストールスクリプトを再実行するか、`docker compose pull && docker compose up -d` を実行します。バージョンを完全にそろえる必要はありません。VRCX-0 がレコーダーの更新を求めたときに更新してください。それまでは補完が止まりますが、記録は失われません。

## トラブルシューティング

| 症状                     | 確認すること                                                                                                                                                       |
| ------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| レコーダーに接続できない | コンテナが動いているか、ファイアウォールでポートが開いているか、アドレスが正しいか。macOS では **ローカルネットワーク** で VRCX-0 を許可します。                   |
| パスワードが違う         | VRCX-0 のパスワードをレコーダーのパスワードと一致させます。                                                                                                        |
| 別のアカウント           | VRCX-0 で使っているアカウントでレコーダーにログインし直します。                                                                                                    |
| 正式版とベータ版の不一致 | 正式版の VRCX-0 には `latest`、ベータ版には `beta` を使います。                                                                                                    |
| ログ                     | インストール先で `docker compose logs` を実行します。Windows ではレコーダーのウィンドウにエラーが表示され、`--headless` で起動した場合はコンソールにログが出ます。 |

## データとセキュリティ

- 記録と VRChat のログイン情報はデータの保存先に、パスワードで暗号化して保存されます。
- 「レコーダーにパスワードを保存」をオンにすると、セッション切れの際にレコーダーが自動で再ログインできます。オフの場合はログイントークンだけを保存します。
- パスワードを変更すると、未補完の記録、VRChat のログイン、Webhook は破棄されます。先に VRCX-0 で一度補完してから `password` を書き換え、`docker compose up -d --force-recreate` を実行し、VRCX-0 で新しいパスワードを使って接続し直し、レコーダーを VRChat に再ログインさせてください。
- VRCX-0 が取得した記録はレコーダーから削除されます。

## アンインストール

VRCX-0 で「接続を解除」を選ぶと、補完した後にレコーダーを VRChat からログアウトさせ、レコーダーの設定を削除します。その後 `docker compose down` を実行し、インストール先を削除してください。

## ライセンス

サードパーティのライセンス表記は各リリースに添付され、イメージ内の `/usr/share/licenses/vrcx-0-logger/` にも含まれています。イメージを自分でビルドする場合は、リリースの実行ファイルを `crates/logger/dist/vrcx-0-logger-amd64` と `crates/logger/dist/vrcx-0-logger-arm64` に置き、`LICENSE` とリリースの `THIRD_PARTY_NOTICES.txt` を `crates/logger/dist/` にコピーしてから `docker build crates/logger` を実行します。
